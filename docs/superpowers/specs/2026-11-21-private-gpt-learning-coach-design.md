# Plus 专属 GPT 学习助手：自动读取进度与推荐词汇（设计稿）

## 1. 已知目标与当前状态

用户已说明使用 ChatGPT Plus，希望避免单独购买模型 API 额度、不重复复制粘贴学习进度，并让助手依据掌握表现和词汇储备推荐下一步学习。

此前已选择网站开放注册，管理员可停用普通账号；AI 辅导第一版按仅本人使用设计。本文补充 `2026-11-20-accounts-and-admin-design.md`，没有实现账号、云端服务或 GPT 工具。

当前网站为 GitHub Pages 静态单页。300 词和计划保存在浏览器，尚无云端同步及受保护的数据接口。现有 `dictionaryId` 绑定整份词库，扩展词库时需要迁移，不能直接替换数组导致进度校验失败。

## 2. 推荐路线与替代方案

推荐：保留背词网页，增加账号与云端数据；在用户 Plus 账号中创建仅自己可见的 GPT，通过 Actions 读取个人记录、提交推荐草稿。学习在网站，对话在 ChatGPT。

其他路线：

- 网站内嵌模型 API：可在原页面聊天，但需要独立模型 API 计费，不符合用户本次费用要求。
- 手动复制进度：简单，但用户已明确认为麻烦。
- 完全由网站本地规则推荐：无需模型 API，可作为网站常驻兜底；不能代替用户希望获得的对话式辅导。

本文推荐组合“网站规则排程 + Plus 专属 GPT 辅导”。所有技术默认值是方案建议，尚待用户确认后实施。

## 3. 能力与费用边界

- 模型回复在 ChatGPT 中产生，遵循用户 Plus 的消息、模型和工具限制；不创建网站的 OpenAI 模型 API 项目，不配置 OpenAI 模型 API key。
- 数据接口只是自己网站的受保护读写接口，不是收费模型接口。
- 网站数据库、函数托管及注册邮件存在各自配额与服务成本，可优先评估免费方案，不能承诺所有服务永久免费或无限量。
- 需先在用户自己的 GPT 编辑器验证 Actions 可用，并选择支持 Actions 的可用模型；不假定所有模型、模式及工作区都支持。
- 必须通过真实账号和真实 HTTPS 工具调用验证，不把设计描述当作已验证产品能力。
- 网站按钮只能打开专属 GPT，不会把 Plus 聊天嵌入原网页，也不会继承当前这段聊天。
- “自动读取”是对话触发工具读取，而不是 24 小时后台监控；首次连接及部分工具操作可能有平台授权提示。

接入时核对的官方资料：

- https://help.openai.com/en/articles/8554397-creating-a-gpt
- https://platform.openai.com/docs/actions/introduction
- https://platform.openai.com/docs/actions/authentication
- https://help.openai.com/en/articles/9039756-billing-settings-in-chatgpt-vs-platform

当前执行环境之前访问官方帮助页被网络代理拒绝，本文不引用未经核实的最新套餐数字、具体 UI 位置或工具额度。正式接入前以官方说明及用户编辑器实测为准。

## 4. 用户使用流程

### 首次设置

1. 部署账号、数据库与数据接口，网站登录后确认导入当前浏览器旧进度。
2. 网站所有者的用户 UUID 在后台设为本次助手的唯一数据所有者，不通过邮箱字符串是否一致或谁先注册来判断。
3. 用户在自己的 ChatGPT 账号中创建专属 GPT，设置为仅自己可用。
4. 导入我们准备的 OpenAPI 工具说明、辅导指令，并在专用鉴权设置填入网站生成的连接口令；不把口令写进 GPT 指令、聊天或知识文件。
5. 在网站保存专属 GPT 的打开链接，手机和电脑登录各自账号后均可使用。

### 每次学习

1. 网站本地先保存作答并同步云端，显示已同步时间和状态。
2. 点击“打开我的学习助手”；若本机尚有未同步数据，先提示同步，失败时明确说明助手只能看到上次同步记录。
3. 在 GPT 中说“安排下一次学习”“帮我复习常错词”等，助手先查询最新摘要，再按需读取测试表现和候选词。
4. 助手给出词组、复习与新词配比、推荐理由以及依据不足的地方。
5. 用户要求保存时，助手提交推荐草稿；回到网站查看草稿，点击“采用”才将其用于下一学习日。不需要手工复制词表。
6. 若期间已在另一设备继续学习，旧草稿标为过期，重新生成或复核，不能覆盖新进度。

## 5. 网站功能

- 登录、个人进度、管理员停用与恢复：沿用账号设计，普通账号可背词但不能使用本人的 GPT 连接。
- 学习面板：继续保留翻卡、英语朗读、当天最多 43 词、未掌握和未完成词顺延。
- 显示全局认识数、经过测试的掌握程度、待复习词、当前任务和最近同步时间，区分自评与检测。
- 添加学习助手入口、待采用推荐列表及采用/忽略操作。
- 添加简短能力检测、隔天或更久后的复测；错题记录由网站计分。
- 当前规则排程在 GPT 限额、连接失败时仍然可用，不把日常背词依赖于每次 GPT 都成功响应。

## 6. 专属 GPT 的辅导功能

- 当前词的释义、常见搭配、近义词辨析、词形与例句解释。
- 根据当日错词出题，要求用户先回答，再解释答案。
- 解释反复遗忘的词，改换例句或增加上下文练习。
- 根据近期测试表现提出合适的新词数量、复习比例和学习节奏。
- 从经过核对的候选词库中选择下一组词，说明原因。
- 查看当天或近期学习报告，明确引用的数据时间与样本量。
- 按用户要求保存建议；普通闲聊不自动改动网站任务、掌握标记或历史成绩。
- 不根据一两次自报“认识”声称精确测出了词汇总量、智力或固定学习能力。

## 7. 如何评估掌握表现与词汇储备

现有按钮记录主要是自评，不足以可靠判断总体水平。推荐依据分成三个层次：

1. 自评：认识/不认识、看过答案后再作答、主观信心。旧数据保留，明确标为自评，不冒充客观测试成绩。
2. 及时检测：不先展示答案的词义选择、拼写或语境填空，记录首答和是否看过提示。
3. 延迟保持：隔天及后续复测的正确率，区分短暂熟悉与较稳定掌握。

初始可用约 20–30 个跨难度抽样题粗分水平；题数、范围及置信度需要实测调整。它不是精确词汇量测验，不能仅凭 300 词宣称用户掌握了几千词。

逐词记录至少包含稳定 word_id、自评结果、检测来源、首答正确性、是否提示、最后检测时间、延迟复测结果及下次建议复习时间。

不以耗时直接推断能力差；中途离开页面、设备差异、网络与读题习惯都会影响时间。

网站客观题由明确的答案规则计分；GPT 闲聊中的用户自述或 GPT 主观评分单独标注，不直接当作可信客观成绩。

## 8. 选词与任务推荐

- 推荐优先级：未完成/仍不熟的顺延词 → 容易遗忘和到期复测词 → 难度合适的新词。
- 保留每天最多 43 个不同学习词的上限；复习不额外堆叠 43 个新词。
- GPT 可以建议降低当天数量，例如复习 20 词加新词 10 词；顺延任务不会因模型建议而被丢弃。
- 网站后端先筛选候选词，排除不适合的难度和重复词，再将有限候选词交给 GPT。
- GPT 返回候选词的稳定 ID、复习/新词分类和推荐理由；后端拒绝不存在的词、重复 ID、超额或违反必需顺延规则的方案。
- 如果必需顺延词已占满每日上限，新词继续等待；其他复测任务保留在到期队列，不被删除。
- 初始用现有 300 词验证全流程。要推荐这 300 个词以外的正式任务，需先准备有来源、等级及释义例句审校的扩展词库。
- 扩展目标沿用用户原要求：英语四级常用词，不引入六级、雅思或专业词汇。作为待确认的实施默认，第一批候选库建议共 1000 个不同词，含原有 300 词；按内部的“基础常用 / 四级常用 / 四级拓展”分组，不冒充官方难度或频次排名。新增加的 700 词需记录可复用来源、核对音标与双语例句；没有可靠来源及审校结果的条目不对外推荐。
- 1000 词是候选库容量，不是立即新增的学习量。原有 300 词任务保留；用户采用下一批建议后才逐步增加学习集合。上述数量是方案建议，不是用户已确认的新词数要求。
- GPT 在聊天中额外举出的词可解释，但未经词库核对不能直接写成正式卡片，避免捏造音标、释义或“官方高频”标签。

## 9. 数据模型与旧进度迁移

在原账号设计基础上增加：

- `word_catalog`：稳定 word_id、单词、音标、释义、双语例句、难度标签、来源、审校状态和目录版本。
- `word_evidence` / `assessment_events`：每个用户每词的自评、检测和延迟复测证据；记录应有事件 ID，重试不得重复计数。
- `recommendations`：用户、建议 ID、状态、来源、候选集/词库版本、生成依据的 progress_revision、词 ID 及理由、创建时间和有效期。
- `coach_connection`：唯一站点所有者 UUID、连接凭据摘要、启用状态与可用权限；只有受信任后台能管理。

学习进度使用 schema_version 与独立 catalog_version。现有 v2 的词条字符串映射为初始稳定 ID，保留历史、已认识词和剩余任务；加词库条目不能导致 `dictionaryId` 不匹配后把进度重置。

用户的全部候选词库、当前学习集合、已认识/已检测证据分开保存。扩展词库不强迫把全部新词一次塞入未完成列表，也不把旧自评记录清零。

多设备写入延续版本比较；迁移前保留原始副本，迁移和导入均需可重试且不会重复增加事件。

## 10. GPT 数据接口与授权

### 自用第一版的授权选择

为保持配置量可控，推荐仅自己可见的 GPT 使用一枚随机强连接口令；服务端将它固定映射到网站所有者 UUID。这是网站数据访问凭据，不是 OpenAI 模型 API key，不产生模型 API 充值要求。

- 浏览器网站仍使用自己的正常登录令牌。
- GPT 口令仅保存在 GPT 的 Actions 鉴权设置；后台保管凭据摘要，接收时验证，不在响应、日志或对话中返回。
- 口令授权固定单一账号，不接受模型或请求体指定其他 user_id。
- 每次请求仍检查所有者账号启用状态，可停用连接或轮换口令。
- 独立 GPT 路由使用完整的自定义鉴权；不能因为网关不接受此口令作为用户 JWT 就暴露匿名接口。普通网站 API 继续保留登录验证。
- 模型可见的 OpenAPI 说明、GPT 指令及网页代码均不含凭据。
- 此模式无法逐人识别 ChatGPT 使用者，必须保持 GPT 仅自己可用。以后需要分享 GPT 或支持多人 AI 时改用按人授权的 OAuth，而不是分享这枚凭据。

若用户希望从第一版开始采用 OAuth，可替换为标准授权码接入；但需真正提供兼容 GPT Actions 的授权/令牌端点。不能把网站能通过 Supabase 登录，误认为 GPT Actions 的 OAuth 服务端已自动存在。

### 建议的最小接口

| 接口 | 用途 | 权限 |
| --- | --- | --- |
| GET /coach/summary | 最新摘要、日期、同步时间、revision、统计 | 只读固定所有者 |
| GET /coach/evidence | 常错词与检测证据，分页 | 只读固定所有者 |
| GET /coach/candidates | 已筛选的复习/新词候选及候选集标识 | 只读固定所有者 |
| POST /coach/recommendations | 保存推荐草稿，含幂等 ID、来源 revision | 固定所有者的草稿写入 |
| GET /coach/recommendations/{id} | 确认保存结果，避免 GPT 口头声称已保存 | 只读固定所有者 |

网站端通过自己的登录接口读取、采用或忽略建议。GPT 不获得修改账号角色、读取其他用户、标记已掌握、删除历史或直接覆盖学习计划的接口。

摘要返回有限数据，不一次发送全部聊天历史与学习事件。每次助手给出依赖进度的建议前先查摘要；必要时按 revision 补查证据和候选词。

推荐草稿写入标记为有副作用的工具操作，遵循平台确认规则；写入限制单次大小、请求频率和权限。

网站“采用”在单一事务中再次检查建议归属、revision、必需顺延词、每日上限和词库 ID；只影响下一学习日，保留当天已作答位置及全部历史。重复采用同一建议返回同一结果，不二次添加任务。

## 11. 隐私、故障与使用边界

- 私有 GPT 的持有人只读取本人学习记录。普通网站注册用户无法访问本人的 GPT 或调用专属接口。
- 给模型的内容只包括必要学习数据，不包含邮箱密码、身份令牌、连接口令、管理员权限数据和他人记录。
- 用户需要知晓发送给专属 GPT 的摘要会由 ChatGPT 处理；必要的隐私设置由用户在自己的账号检查。
- GPT 的跨对话记忆不作为数据源；最新个人情况以网站数据库和同步时间为准。
- “已保存/已采用”必须以服务端成功结果为准；工具失败时直说，不能虚构已看到最新进度。
- 断网、数据过期、会员限额、工具不可用时，网站继续保留本地记录并使用确定性排程；给出重试或重新生成建议入口。
- 其他设备同时学习导致版本冲突时保留本机副本，过期推荐不自动覆盖。
- 读接口有速率、分页和载荷大小限制，避免异常重试耗尽数据后台免费配额。

## 12. 实施顺序与交付

### 阶段 A：小范围可行性验证

在用户自己的 Plus 账号确认能创建仅自己可用的 GPT、配置 Actions，使用纯测试数据验证 HTTPS 读接口、鉴权、工具授权提示及响应格式。没有成功前，不承诺已经实现自动读取。

### 阶段 B：账号与真实同步

落地原账号设计：网站登录、旧记录确认导入、独立云端进度、版本冲突、管理员停用/恢复；配置真实数据库、函数、回跳地址与必要邮件服务。

### 阶段 C：读取与辅导

部署摘要、证据及候选词只读接口，交付 GPT 指令和 OpenAPI 配置；接入网站“打开我的学习助手”，验证真实本人记录和跨设备新鲜度。

### 阶段 D：检测、分级词库与推荐回写

补齐能力检测和复测记录，准备经核对的扩展候选词库及非重置式迁移，接通推荐草稿、网站采用及幂等检查。保留规则排程作为兜底。

用户需要亲自完成：创建自己的数据后台项目及 Plus 私有 GPT，填写后台/GPT 安全配置。助手可交付网站代码、迁移、函数、测试、GPT 指令、OpenAPI 说明与配置步骤，但不能通过当前工具代替用户操作个人 ChatGPT 的 GPT 编辑器。

## 13. 验收

- 不配置 OpenAI 模型 API key，真实 Plus GPT 能调用受保护接口。
- 错误或撤销连接口令、停用所有者账号均被拒绝；篡改 user_id 不能读他人数据；接口无凭据不能读取真实进度。
- 两个普通网站账号的数据互相隔离，普通账号无法调用本人的 GPT 接口或管理连接。
- 新设备登录显示云端记录；离线未同步记录有明确提示，GPT 不冒充读取成功。
- 旧 300 词进度完整保留；扩充词库不清空认识数、作答和历史天数。
- 自评与客观检测被区分，缺少证据时不声称精确测得词汇量。
- 推荐来自可用候选，遵守顺延优先和 43 词上限，重复请求/采用不重复排词。
- 旧 revision 的建议不覆盖新进度；GPT 无法自行改已掌握状态或删历史。
- 私有 GPT 与网站端真实跑通“学习并同步 → 读摘要 → 推荐 → 存草稿 → 网站采用 → 下一天生效”。
- 当工具失效、会员限额或数据接口超额时，基础背词和已保存进度仍可用。

本文件是设计路线，尚未创建服务、GPT 或数据接口，也未将学习记录发送给任何新服务。
