# 开放注册、个人进度和管理员后台（待确认设计）

## 用户意图与已确认范围

用户已选择：开放注册，任何人都可以注册，管理员可以停用账号。

目标是让不同用户的学习记录独立保存，同一账号在手机和电脑之间接续学习，站点所有者能管理登录人员。保留现有 300 词、弹性顺延、英语朗读和响应式界面。

本文件是待确认的方案，尚未实现账号功能，也不代表后台服务已开通。技术选型和下述默认值是实现建议，并非用户已逐项确认的要求。

## 现状与约束

- `index.html` 是无构建步骤的静态单页，由现有 GitHub Pages 发布。
- `wordspace-adaptive-v2` 存储在浏览器 `localStorage`；没有账号或跨设备同步。
- 学习计划包含 dictionaryId、mastered、pending、days、activeDay，并通过 `validPlan` 检查数据一致性。
- 当前仓库没有账号客户端、数据库、服务端或人员管理功能。
- 已检查现有环境配置与相关变量名，没有 Supabase、Firebase 或数据库服务绑定。
- GitHub Pages 无法提供账号数据库或保管管理员服务端密钥，需要接入后端。
- 单页代码及词库仍可公开读取；要保护的是账号、个人进度和管理员操作。网页登录不等于隐藏公开仓库中的词库源码。

## 方案比较

注册准入方式曾考虑邀请制、注册后审核及开放注册。用户已选择开放注册，因此不实现邀请审批门槛。

后台实现可采用：

1. **推荐：现有 GitHub Pages + Supabase Auth / Postgres / Edge Functions。** 保留网址和无构建前端，账号、数据和管理接口由托管后台提供；需要在站点所有者的 Supabase 项目配置数据库、函数及邮件发送。
2. **自建应用后台 + 数据库。** 可更自由地控制部署，但增加服务器、HTTPS、备份和身份认证维护工作；没有现成服务器配置，不作为本次默认路线。

推荐第一种。若用户另有现成后台服务，须先调整技术接入方案。

## 用户流程

### 登录与注册

- 访客首先看到邮箱、密码登录界面，可以注册及找回密码。
- 开放注册，邮箱验证成功后可学习，无需管理员审批。
- 密码存储、验证、重置与会话刷新交给身份服务；不在网页代码或浏览器自建用户密码表。
- 登录后读取账号状态及该账号的云端进度，读取成功后展示学习页面。
- 退出仅退出当前设备；停止朗读，清空界面中的账号数据和管理员列表，返回登录界面。
- 停用账号显示明确提示，不能继续读写云端进度；恢复后可重新使用原有进度。
- 邮箱确认和密码重置必须配置允许的站点回跳地址，并在实际公开网址测试。

### 个人进度与迁移

- 每个账号有独立云端记录；本地缓存、待同步修改按用户 UUID 分开存储。
- 保留现有弹性计划数据格式，继续使用 `validPlan` 校验，不重写词库或顺延规则。
- 首次登录且云端没有记录时，检测本浏览器的旧进度：让用户明确选择“导入本机进度”或“从头开始”。不能自动归入正在登录的账号，避免共用设备混入别人的记录。
- 导入成功前不删除旧记录；记录导入归属，其他账号不再自动收到同一旧记录的导入提示。
- 若云端已有进度，默认使用云端，不用旧访客数据覆盖。
- 在本地保存、在后台同步，明确展示“已同步 / 待同步 / 同步失败”。断网修改留在当前账号缓存，重连后再尝试同步；首次未能验证登录及账号状态时不绕过登录进入应用。
- 切换账号不把上一个账号待同步的内容写入新账号。退出前将未同步修改留在原账号缓存。
- 跨设备同步采用版本号比较；加载或回到页面时刷新云端版本。若云端被其他设备修改，暂停覆盖，保留本机副本，让用户选择加载最新云端或明确用本机版本替换。
- 不直接拼接两个独立修改的学习计划，以免引入重复词、丢词或错误天数。

### 管理员

- 普通用户只能管理自己的学习记录，不能查看人员列表或设置角色、账号状态。
- 管理员可以查看账号邮箱、注册时间、账号状态和最近登录时间；支持搜索、分页、停用和恢复。
- 管理员列表不展示密码或其他用户的详细学习记录，不提供普通用户提升权限的入口。
- 停用保留账号与进度，恢复后继续；本次不做永久删除账号、批量导出或多管理员授权界面。
- 本次默认一个站点所有者管理员。先注册并验证自己的账号，再由项目所有者通过后台以该账号的 UUID 授予管理员权限。
- 不把第一个注册者自动变成管理员，不从用户可修改的元数据或前端配置认定管理员身份。
- 管理员不能停用自己；此限制由后端检查，而非只隐藏按钮。
- 停用立即阻止后台接口及数据库读写，包括已有登录令牌的请求。离线设备无法立即收到状态变化，恢复联网或重新进入时重新检查；不承诺远程抹除设备上已存在的本地副本。

## 数据与权限边界

### 账号资料

`profiles` 保存用户 UUID、邮箱、注册时间、角色及账号状态；敏感角色和状态只能由可信后端修改。资料初始化从身份服务生成，忽略注册者自报的管理员身份。

普通用户可读取自己的必要资料，包括停用状态，但不能读取其他用户资料或自行激活账号。管理员人员列表由后端接口提供最少字段。

### 学习记录

`study_progress` 至少包含：`user_id`（主键）、`dictionary_id`、`state`（JSON）、`revision`、服务器生成的 `updated_at`。

- 按身份服务验证的用户 UUID 隔离数据；不能相信请求体里填写的用户 ID。
- 数据库行级权限检查账号当前状态，禁止停用账号读取或写入进度。
- 读操作允许本人读取；写操作走带版本检查的数据库函数，不开放绕过版本比较的直接表写入。
- 原子比较 expected_revision，成功才增加 revision；版本不一致返回明确冲突。
- 后端校验 JSON 基础结构和载荷大小；前端 `validPlan` 检查完整计划不漏词、不重复的规则。

### 管理接口

Supabase Edge Function 接收登录令牌，验证身份并从数据库核对管理员身份和启用状态，提供分页查询及停用 / 恢复操作。

- 浏览器仅持有公开的项目 URL 和 publishable key（或兼容的 anon key）。
- service_role / secret key 只在托管函数的服务端环境中使用，绝不出现在 Git、网页、浏览器存储或聊天里。
- 用户提交邮箱、角色、user_id 或修改网页 DOM 都不能提升权限。
- 服务端必须限制允许的来源并处理跨域；来源限制不替代身份验证。

## 前端接入

- 保持纯 HTML / CSS / JavaScript，不增加构建步骤；保留现有网址。
- 推荐使用固定版本的官方身份服务客户端，具体内嵌或引入方式由实现者决定，并记录版本和来源。
- 登录完成之前不要运行学习计划加载、跨天顺延或向本地账号缓存写入的初始化过程。
- 将现有学习逻辑接入账号专属的存储与同步层，继续复用音频、词表与顺延实现。
- 账号未配置、请求失败和邮箱未验证必须显示真实状态，不做假登录、默认管理员或伪造云端同步。
- 管理员后台在同一单页内切换，不能只靠前端隐藏按钮实现权限。

## 外部配置前提

需要站点所有者的 Supabase 项目。当前环境未发现可复用项目。

部署需要：

1. 项目 URL 与公开 publishable key，用于网页客户端；这些公开配置不授予管理员权限。
2. 执行数据库迁移，部署管理函数，配置 GitHub Pages 的网站地址、登录回跳地址及跨域来源。
3. 为公开注册配置可实际发送确认、找回密码邮件的邮件服务。不能假定默认测试邮件额度及收件人限制能支持所有注册者；具体限制在接入时查官方文档。
4. 站点所有者注册、验证账号后，以用户 UUID 设置管理员。

无需在聊天中提供密码、service_role key 或邮件服务密码。后台密钥由项目后台的安全配置或已有安全绑定提供。

## 验证与发布

- 先使用本地后端或测试项目验证身份与数据库权限，再验证真实托管项目及邮件回跳。
- 两个普通账号分别注册、验证、登录；互相无法读取或写入资料及学习记录。
- 同一账号跨两个浏览器接续学习，并测试同时修改时的版本冲突处理。
- 共用浏览器切换账号，确认进度、缓存、待同步修改和管理列表不串号。
- 有旧进度、无旧进度、云端已有进度三种迁移路径，确认取消导入或失败后不会丢失原数据。
- 普通用户直接调用管理接口被拒绝；伪造前端角色或注册元数据不能获得管理员权限。
- 管理员停用有会话的账号后，旧令牌也不能读写后台；恢复保留进度；不能停用管理员本人。
- 邮箱确认、找回密码、令牌刷新、退出、断网缓存、重新联网和同步冲突均需验证。
- 回归现有 300 词、弹性日期、英语朗读及手机布局。
- 未配置真实后台时，只能报告本地或测试项目结果，不能宣称网站已具备可用登录和管理员功能。
- 功能验证完成且实际后台可用后再推送影响页面入口的变更，避免把现有网站发布成无法登录的配置占位页。

## 明确不包含

支付、收费会员、短信登录、微信登录、邀请或人工审核、永久删除、跨账号共享进度、多管理员管理和管理员读取用户密码。

尚需确认推荐的托管后台方案。后端项目和邮件服务若未创建，是部署前提；不能靠前端代码替代。
