# 网页自动学习效果检测

用户已选择：在背单词网页点击后自动出题，不需要每轮先到聊天中请求。

## 目的

检验已学单词的词义识别和例句应用，并通过延迟复测观察保持情况。沿用现有词库、网页和账号检测记录，不调用收费模型 API。

## 已确认的方案与取舍

- **网页自动组题（用户选择）**：用已审校的单词、释义和例句组题，点击即可开始；无需新增模型服务或由聊天逐轮发布试卷。
- **聊天出题后同步**：可定制开放题和新语境，但每轮需要来聊天，并新增试卷存储和同步接口；本次不做。

## 本次拟实现的流程

1. 将现有“不看答案，测一测”升级为“学习效果检测”，每轮最多10个不重复的已学单词。已学范围为本人学习日中实际作答过的词；没有学过的词不作为考查目标。
2. 优先抽取已到期的复测词和需巩固词，再补充已学且较少检测的词；不足10词时按实际数量出题。
3. 交替使用“看英文选中文”和“例句中选词”两种选择题。例句必须来自现有已审校词库，并且能准确挖去目标词；无法挖空时改用词义题。答题前不展示答案或中文译文。
4. 每题仅记首次选择；选择后展示正确释义和例句，点击“下一题”继续。中途退出只保留已经作答的检测记录，不将未答题记错。
5. 完成本轮后显示答对数、首次正确率、错词及复习建议；样本不足和未完成会明确标注。正确率反映本轮选择题，不宣称精确词汇量或长期掌握。
6. 沿用现有至少24小时的延迟复测判定；未到期显示“等待复测”，而不是伪造隔天保持率。到期词会在后续检测优先出现。
7. 每题结果沿用当前账号的检测接口保存，教练可通过现有插件读取。保留原有历史成绩和自评掌握标记；本功能不自动改写它们，也不新增学习任务。
8. 页面保留当前网站的浅色样式，支持手机和键盘操作；正在加载、空词集、记录同步失败和本地模式都有明确提示。

## 技术边界

- 优先复用 `web/account.js`、`web/learning-ui.html`、`web/account.css`、共享 Core 及现有 `submit_assessment`。
- 无需改变账号权限、连接口令、推荐草稿流程和数据库历史；自动出题由网页脚本执行。
- 本轮过程和报告在页面内展示；已提交的逐题记录沿用现有云端同步。刷新或切换设备后重新开始一轮，已有检测结果仍保留。
- 不做自由文本自动评分、听写语音识别、模型自动生成新例句和按用时判定能力。

## 验收

- 只抽已实际作答的词，未学词与其他账号词不进入题目；轮内目标词去重，少于10词正常工作。
- 两类题都能可靠判分，答案在作答后揭示，重复点击不重复计分或提交。
- 完成和中断的统计口径正确；复测未到期、历史不足和同步失败不显示虚假结果。
- 原有登录、离线缓存、账号切换、学习计划和推荐采用功能正常；本地版与云端预览页均更新。
- 运行相关单元测试和网页交互验证后，再通过现有 GitHub Pages 发布。

## 现状检查

当前代码从整个已审校词库随机抽题，与已学范围无关；已有逐题检测存储和24小时复测统计，可直接复用。基线26项单元测试中25项通过，1项在 Windows 清理预览子进程临时目录时触发 `EBUSY`；需在后续验证中单独核实。
