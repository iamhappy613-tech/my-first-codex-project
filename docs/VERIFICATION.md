## 验证结果

2026-11-21 运行 `npm run test:all`：26 项单元测试、13 项真实 PostgreSQL 测试、24 个浏览器场景全部通过；全部 1000 个候选词及双语例句在 320/390px 卡片两面通过布局检查；自包含 HTML 和数据库种子与源文件一致。两个后端入口通过 Deno check。

数据库测试使用隔离 PostgreSQL 和模拟 auth.uid 声明；浏览器和 HTTP 测试使用受控服务响应。它们不能替代真实服务验收。当前执行环境访问该 Supabase 域名和 GitHub Pages 域名被网络代理拒绝，因此没有声称线上登录、邮件、函数或个人 Plus 已连通。

一次独立整体审阅发现的预览凭据暴露、采用推荐后继续答题、采用请求期间丢作答、NULL 绕过版本检查、小份推荐被强行补满、失效刷新令牌、测试入口顺序和账号检测残留问题均已修复。回归测试先复现失败再验证通过；推荐流程还复现并修复了空同步请求阻塞后续保存的问题。

## 实现取舍

| 决定 | 原因 | 判断错误的影响 |
| --- | --- | --- |
| 沿用当前 main 工作区并按原授权推送 | 用户明确要求提交 main，当前为隔离云端工作区 | 发布缺陷会直接影响正式页面，因此发布前整体审阅并运行回归 |
| 已掌握词的延迟检测独立记录，不静默撤销旧版自评掌握 | 保留历史记录，明确区分认识与检测证据 | 自评分数可能高于实际熟练度，因此界面和 GPT 均明确数据范围 |
| 两个 HTTP 函数使用处理器鉴权，关闭平台统一 JWT 网关检查 | GPT 使用独立口令；管理员令牌向 Auth 验证，再由数据库核对角色；普通数据库接口仍启用 RLS | 处理器若绕过鉴权会暴露数据，已覆盖错误凭据、停用旧令牌、越权及用户 ID 注入检查 |
| 真实邮件、托管鉴权、函数部署和 Plus 调用作为外部验收保留 | 必须通过用户自己的项目及账号操作；当前只有公开配置且网络不通 | 服务端配置错误时功能可能不可用，故验收前不启用正式首页云端模式 |
| 扩展词条依据固定版本来源，释义例句由项目编写核对，不代表独立语言专家认证 | 已记录四级标签、参考频率、发音来源和授权；保留原 300 词任务 | 仍可能存在语言内容误差，支持后续订正，不冒充官方真题排名 |
